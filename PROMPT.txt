协作白板按仓库里的 compose 拉起来之后，我用浏览器打开页面，后端进程自己退了。状态栏停在「连接中…」，点矩形、圆形都落不下去，画布一直空着。仓库里那二十来个用例我跑过全绿——降级回弹、只读被拒、属性合并、重连追增量、撤销按人、连线贴锚这些都在。不挂数据库的时候也看不出这件事。一接到真实库、同一张画布被两路几乎同时加入，进程就没了。

容器日志会打 duplicate key value violates unique constraint "canvases_pkey"，随后 server 变成 Exited(1)，连 /health 都拒绝。慢慢来、等第一路已经拿到 snapshot 再让第二路进，有时能撑住；把间隔压到几十毫秒内，必现。我是这么打的：环境起来后连两条 WebSocket 到 /ws，几乎同时各发 join——画布 id 都用 room-bug，lastSeq 都是 0；一路 name 甲、sessionId s1，另一路 name 乙、sessionId s2。服务端直接退出，两边都收不到 snapshot。浏览器里把带井号的同一地址开两个窗口，先开的那个刚转圈或刚连上，后开的一进，全员掉回「连接中…」。

希望修好之后，同一张画布被两路甚至更多路几乎同时加入，进程还活着，/health 继续 200，每路都收到 snapshot；随后一方放下矩形，另一方能马上看到。现有那组用例继续全绿，降级回弹、只读写被拒、同属性按到达顺序收敛、重连、撤销互不牵连、连线贴合、删图元不留悬空端点，这些都不要动。请再补一条会打到真实落库的回归：并发加入同一画布时进程不退出、双方都能拿到快照。验收以这条为准，现有单测绿只是底线。
